4. REGISTRO Y CONTRASENA CON HASH
============================================================
UserService rechaza un email duplicado, codifica la contrasena con BCrypt y
guarda el usuario mediante el repositorio.

CAPTURA: evidencias_taller_punto_22\code-user-service.png
Servicio de registro, deteccion de email existente y llamada a
PasswordEncoder.encode antes de guardar.

CAPTURA: evidencias_taller_punto_22\code-mvc-tests-2.png
Pruebas de registro exitoso, rechazo de email duplicado y comprobacion de
validacion del lado servidor.

La suite confirma que una contrasena codificada tiene formato BCrypt y que el
PasswordEncoder puede comprobarla. Por seguridad no se muestra el hash completo
ni se consultan valores de contrasena de usuarios reales.

Consulta SQL segura para contar valores con prefijo BCrypt sin revelar los
valores almacenados:

  SELECT COUNT(*) AS bcrypt_encoded_passwords
  FROM users
  WHERE password LIKE '$2%';

La prueba automatizada tambien comprueba el prefijo BCrypt y la verificacion de
la contrasena, sin imprimir el hash.

11. ANALISIS TECNICO Y APRENDIZAJES
============================================================
  Persistencia:
  La entidad Users se mapea a la tabla users. Spring Data JPA implementa las
  consultas findByEmail y existsByEmail a partir de los nombres del repositorio.

  Migraciones:
  Flyway versiona el esquema con SQL reproducible. Hibernate valida el esquema
  existente; no se usa para reemplazar las migraciones de produccion.

  Autenticacion y autorizacion:
  DaoAuthenticationProvider valida credenciales usando UserDetailsService y
  PasswordEncoder. SecurityFilterChain determina que /users requiere una sesion
  autenticada.

  Proteccion de contrasenas:
  BCrypt almacena un hash no reversible. La autenticacion compara la contrasena
  recibida con el hash; el sistema no necesita recuperar el texto original.

  Validacion:
  La validacion HTML ayuda al usuario, pero una solicitud HTTP puede omitirla.
  Por eso las restricciones tambien se verifican en el servidor con Jakarta
  Validation, y los errores se muestran en la plantilla.

  Pruebas:
  UsersRepositoryTests verifica persistencia en MySQL. MockMvc prueba las
  respuestas HTTP, la seguridad, el renderizado Thymeleaf y el comportamiento
  de registro/login/logout sin exponer datos de cuentas reales.
